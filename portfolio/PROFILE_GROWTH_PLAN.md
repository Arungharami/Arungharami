## Work sequence

### 1. Make Biomedical Hybrid IR easy to try

Start with the [existing roadmap](projects/biomedical-hybrid-ir.md), repository quick start, and October 4 engineering review.

- Run the documented baseline from a clean environment.
- Record environment, commands, output, runtime, and any setup fixes.
- Verify one query example against the committed ranking artifacts.
- Capture a short walkthrough showing a query, method comparison, and supporting evidence.
- Make the first README screen explain purpose, setup, results, and current portal behavior.

Accept when another person can repeat the example from the instructions. Do not describe exported rankings as arbitrary live inference.

### 2. Repeat for DriftCVE-NLP and TinyML

Use the [DriftCVE roadmap](projects/DriftCVE-NLP.md) and [TinyML roadmap](projects/Drift-Robust-TinyML-Research-System.md).

For DriftCVE, use its actual default branch and pinned dataset revision. For TinyML, demonstrate a host-side workflow and keep hardware measurements pending until recorded on real equipment.

Accept when each project has one reproducible example, an evidence link, and an accurate demonstration.

### 3. Enable small contributions

Search existing issues before adding any task. Reuse equivalent issues.

Good candidate tasks arise from actual setup or documentation problems found during reproduction. Each task should name the problem, relevant files, expected outcome, and verification command. Apply beginner-friendly labels only when scope and prerequisites make the work suitable.

Accept when a contributor can understand one useful task without a private briefing. Do not create empty issues merely to make the repository appear active.

### 4. Share a meaningful release

Prepare a short demonstration and a concise explanation of a verified improvement. Link directly to its code, example, or result. Share through selected professional channels and relevant communities under their posting rules.

Useful subjects:
- Biomedical IR: when lexical and semantic retrieval disagree, using a verified query example.
- DriftCVE: evaluating on later vulnerability descriptions without chronological leakage.
- TinyML: why host numerical equivalence and physical latency are separate measurements.

Invite reproduction or specific feedback. Do not promise follower growth or send unsolicited messages through automated tools.

## Sustainable cadence

Choose one deliverable at a time. A practical initial cadence is one focused project improvement and one useful explanation per week, with time to answer questions. Reduce frequency if it interferes with maintaining the projects.
